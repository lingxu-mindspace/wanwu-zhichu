# 万物之初 · 技术验证案例

一个"活的世界模拟器"游戏的设计文档，加 7 个可复跑的技术验证原型。

这不是一个游戏成品，也不是可玩 Demo。它是一套设计加一组用来回答"这些设计在技术上做不做得出来"的最小原型。2026-11-07 在本机全部复跑，日志和命令都在仓库里。

## 这个仓库里有什么

| 部分 | 内容 |
|---|---|
| `docs/` | 验证报告（含复跑数字与勘误）、3 篇设计样本 |
| `validation/` | 7 个 Node/TypeScript 验证原型 + 本次复跑日志 |
| `validation/results/2026-11-07/` | 7 份原始输出，未加工 |

设计样本只放了不涉及完整事件链、NPC 对话库与战斗数值的三篇：共语者机制、接引仪式、UE5 原型启动计划。八卷总设计文档不在此仓库。

| # | 验证项 | 性质 | 本次结果 | 判据 | 结果 |

| v1 | 部位伤害判定 | 实测原型（本地 WebSocket） | 5 种模拟延迟下均为 50/50 命中 [S] | 判定在服务端完成、延迟可解释 | 通过 |
| v2 | 天道事件流 + 哈希链日志 | 实测原型 | 100K/s 场景 63,413 条/秒 [S] | 事件可流水处理并写入日志 | 通过（吞吐受定时器粒度封顶） |

| v5 | NPC 社交与记忆 | 实测原型 | 10,000 NPC、4,996,290 条记忆，查询 0.0112 ms [S] | 单次记忆查询亚毫秒级 | 通过 |

## 怎么复跑

```bash
cd validation/v4-map-streaming
npm install
npx tsx src/map-streaming.ts
```

v5 默认跑 1,000 个 NPC；要与报告里的 10,000 NPC 口径一致：

```bash
cd validation/v5-npc-social
NPC_COUNT=10000 npx tsx src/npc-social.ts
```

每个目录的运行命令见 `validation/README.md`。

## 如实说明

- **不是原型产品**：没有美术、关卡、联网服务或可玩循环。验证的是局部技术可行性。
- **命中率 100% 是测试构造**：v1 与 v8 的攻击瞄准了身体，测的是判定链路是否贯通，不是实战命中率。
- **v4 的帧时间不是实测渲染帧率**：它是按"16 ms + 0.3 × 区块加载耗时"合成的模型值 [A]；真实的只有内存分配和逻辑开销。它验证的是分块管理器的组织方式，不是真实 I/O 或渲染性能。
- **v6 是数值仿真**：漂移由模型生成，没有真实网络、丢包或时钟。
- **v8 不按实时节流**：2400 个 tick 用 0.1 秒跑完，报告里的"实时比 0.00x"不代表吞吐能力，只说明测试没有按 20 tick/s 的节拍等待。
- **v2 的吞吐被定时器粒度封顶**：50K/100K/200K 场景实测为 6.4K/63K/73K 条/秒，瓶颈是事件循环的定时器下限，不是处理能力；本次没有测容量上限。日志在内存里，链式哈希不是持久化存储。
- **丢包未模拟**：原型里的 `packetLossRate` 配置没有被读取，所有测试实际为 0 丢包。
- **v1 的客户端文件缺失**：迁移时 5 个文件损坏（全零：客户端 2 个、共享类型 2 个、2026-07 测试结果 1 个），无法恢复；当前 v1 只包含服务端判定与自动化测试。
- **数字有机器依赖**：定时器、GC、CPU 都会影响吞吐与延迟；同一数字在不同机器上会有偏差。
- **旧数字已作废**：2026-07 报告与本次复跑的差异、以及三处测量问题（v1 无法启动、v2 限速器失效、v5 默认规模与报告不一致），逐条写在 `docs/00_验证报告.md` 的勘误表里。
